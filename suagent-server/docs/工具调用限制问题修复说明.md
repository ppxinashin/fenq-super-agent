# 工具调用限制问题修复说明

## 问题描述

在使用 `ToolCallLimitMiddleware` 限制工具调用次数时，即使设置了 `run_limit=5`，agent 仍然会达到递归限制（默认25次），而不是在5次工具调用后停止。

## 根本原因

### 1. 配置传递问题（已修复）

在 `src/agents/my_agent.py` 中，`invoke` 方法错误地将所有配置参数都放入了 `configurable` 字典中：

```python
# 错误的方式
return self._agent.invoke(input, {"configurable": {"thread_id": self.chatId, **(cfg or {})}})
```

这导致 `recursion_limit` 被放在了错误的位置。正确的做法是将 `recursion_limit` 放在配置的根级别：

```python
# 正确的方式
config = {
    "configurable": {"thread_id": self.chatId},
    "recursion_limit": 100  # 在根级别
}
```

### 2. 递归限制 vs 工具调用限制

需要理解两个不同的限制概念：

#### recursion_limit（递归限制）
- **含义**: 限制整个 agent 的最大循环次数
- **包括**: 每次模型调用（决策）+ 工具执行 + 状态更新
- **默认值**: 25
- **配置位置**: config 根级别
- **何时使用**: 防止 agent 陷入无限循环

#### run_limit（工具调用限制）
- **含义**: 限制工具被实际调用的次数
- **统计方式**: 每次 AI 模型决定调用工具时计数
- **配置位置**: ToolCallLimitMiddleware 的参数
- **行为**: 达到限制时跳到 "end" 节点或抛出错误
- **何时使用**: 限制成本、API 调用次数或防止过度使用某个工具

#### 为什么会达到递归限制？

一个完整的 agent 循环包括：
1. 模型调用（决策要做什么）
2. 如果有工具调用，执行工具
3. 将工具结果返回给模型
4. 模型再次调用（基于工具结果做出新决策）
5. 重复...

即使只调用了5次工具，整个流程可能经历了 10-15 次循环：
- 模型决策 → 工具1 → 模型决策 → 工具2 → 模型决策 → ...
- 每个 "模型决策 → 工具执行" 都算多次循环

从日志可以看出，agent 不断尝试新的搜索策略，因为：
- 搜索结果不理想
- AI 认为还没有找到满意的答案
- 没有明确的停止条件

## 解决方案

### 1. 修复配置传递（已完成）

在 `src/agents/my_agent.py` 中添加了 `_build_config` 方法：

```python
def _build_config(self, cfg: dict[str, Any] | None = None) -> RunnableConfig:
    """构建配置字典"""
    config = {"configurable": {"thread_id": self.chatId}}
    
    if cfg:
        # 合并 configurable 中的配置
        if "configurable" in cfg:
            config["configurable"].update(cfg["configurable"])
        
        # 添加其他根级别的配置（如 recursion_limit）
        for key, value in cfg.items():
            if key != "configurable":
                config[key] = value
    
    return cast(RunnableConfig, config)
```

### 2. 改进系统提示词

在系统提示词中明确告诉 AI 应该何时停止搜索：

```python
IMPROVED_SYSTEM_PROMPT = """你是一个智能 AI 助手，名叫 Fenq Super Agent。

重要规则：
- 如果搜索工具返回的结果不相关或无用，最多尝试2-3次不同的搜索关键词
- 如果多次搜索仍然找不到有用信息，应该诚实地告诉用户当前无法找到相关信息
- 不要无限循环搜索，要学会适时停止
- 当你已经尽力但仍然找不到信息时，直接回复用户说明情况
"""
```

### 3. 合理配置限制参数

```python
agent = MyAgent(
    middlewares=[
        get_my_logger_middleware(), 
        ToolCallLimitMiddleware(
            run_limit=5,           # 最多5次工具调用
            exit_behavior="end"    # 达到限制时优雅结束
        )
    ],
    system_prompt=IMPROVED_SYSTEM_PROMPT,
)

# 调用时设置更高的递归限制
agent.invoke(
    {"messages": [HumanMessage(content="...")]}, 
    cfg={"recursion_limit": 100}  # 避免过早达到递归限制
)
```

## 使用建议

### 1. 选择合适的限制值

- **recursion_limit**: 
  - 通常设置为 50-100
  - 如果使用了 ToolCallLimitMiddleware，可以设置更高的值
  
- **run_limit**:
  - 对于搜索任务：5-10 次
  - 对于简单任务：3-5 次
  - 对于复杂任务：10-20 次

### 2. 选择合适的退出行为

```python
# 优雅结束，返回提示信息
ToolCallLimitMiddleware(run_limit=5, exit_behavior="end")

# 抛出异常，用于调试或严格限制
ToolCallLimitMiddleware(run_limit=5, exit_behavior="error")
```

### 3. 监控和调试

使用日志中间件观察实际的工具调用次数：

```python
middlewares=[
    get_my_logger_middleware(),  # 记录所有工具调用
    ToolCallLimitMiddleware(run_limit=5)
]
```

### 4. 针对特定工具的限制

```python
# 全局限制所有工具调用
global_limiter = ToolCallLimitMiddleware(run_limit=10)

# 只限制搜索工具
search_limiter = ToolCallLimitMiddleware(
    tool_name="duckduckgo_results_json",
    run_limit=3
)

# 同时使用
middlewares=[global_limiter, search_limiter]
```
